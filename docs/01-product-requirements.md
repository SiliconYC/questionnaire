# 01 · 产品需求

## 1. 产品目标

建设一个中文感官评价问卷网站，覆盖“设计实验 → 分配任务 → 逐样品评价 → 审阅退回 → 统计导出”的完整流程。第一使用场景是食品样品的感官评价，也可复用到其他具有多样品、同一组指标的评价活动。

网站首先用于演示，但演示版本也应有完整业务行为。真实账户、权限与共享数据在具备外部服务时启用，不能把浏览器本地状态包装成真实注册或多人数据库。

成功标准是：首次访问者不用阅读技术文档，能够进入演示，提交一个样品评价，并在管理员视角看到新增结果；开发者按部署文档可以发布演示版本，具备外部配置后可以验证两台设备之间的数据同步。

## 2. 用户与权限

| 身份 | 主要目标 | 可操作范围 |
| --- | --- | --- |
| 访客 | 了解系统、进入演示、开始真实登录 | 公开介绍、运行模式说明、认证入口 |
| 评价员 `participant` | 完成自己的样品评价 | 分配给自己的实验、草稿、提交记录和退回原因 |
| 管理员 `admin` | 管理实验和结果 | 站点内实验、评价员名单、分配、进度、退回、分析、导出、账户停用 |

V1 是单站点、单管理域；站点所有管理员具有相同数据权限。暂不建设多租户、实验级管理员、付费订阅和组织层级。管理员如需作为评价员参加实验，也必须显式获得任务分配；填写入口不等于以管理权限代填他人记录。

`demo` 提供身份切换，是演示控制台的能力。`live` 的角色只能由服务端验证，页面隐藏或前端路由守卫不能作为权限控制。

## 3. 发布里程碑

| 里程碑 | 可交付内容 | 允许的限制 |
| --- | --- | --- |
| M1 · 完整演示 | GitHub Pages 上的完整业务闭环、浏览器持久化、配置导入导出、真实描述统计与下载 | 身份和邮件流程模拟；不跨浏览器共享 |
| M2 · 真实协作 | 外部认证、PostgreSQL、行级权限、真实分配、跨设备草稿、事务提交、管理审计 | 外部服务、部署与提供方配置必须就绪 |
| M3 · 进阶分析 | 按统计规范实现重复测量推断、配对比较、分析快照与方法报告 | 不满足分析条件时明确不给结果 |

M2 是正式建设目标，不能因为已有 M1 就取消。实现 Agent 应先检查可用的外部资源；资源齐备时继续完成并验收 M2，缺少资源时交付可运行的 M1 和已准备好的接入代码、迁移与准确的配置清单。M3 可独立发布，不阻塞 M1/M2 的数据采集。

## 4. 功能需求

### 4.1 账户与入口

| 编号 | 要求 | 里程碑 |
| --- | --- | --- |
| `REQ-01` | 首页提供“体验演示”和已配置时的“进入真实工作区”，说明当前数据保存位置 | M1 |
| `REQ-02` | 演示支持创建本地演示身份、切换预设身份、模拟注册完成、重置演示；固定提醒仅当前浏览器有效 | M1 |
| `REQ-03` | 真实身份通过外部认证提供方验证；首次验证后创建评价员资料；登录、退出、过期和拒绝授权有完整处理 | M2 |
| `REQ-04` | 管理员权限由可信后台授予；新注册用户默认评价员；账户停用后立即禁止新的业务读写 | M2 |

真实认证的默认选型及 Pages 的边界见 [08](08-security-and-privacy.md)。禁止内置公开的 `admin/admin123` 账户。演示身份可以公开展示，但必须带“演示”标记，不能在真实模式使用。

### 4.2 实验设计

| 编号 | 要求 | 里程碑 |
| --- | --- | --- |
| `REQ-05` | 通过向导创建、编辑草稿实验；配置标题、说明、样品、数值指标和文字题；可复制已有实验 | M1 |
| `REQ-06` | Excel 和 JSON 导入经过预检查、完整错误列表、预览、确认后一次性保存；支持下载模板与配置 | M1 |
| `REQ-07` | 发布前预览评价员页面；发布后固化配置快照；已发布实验的样品、量程和题目不能原地修改 | M1/M2 |
| `REQ-08` | 支持选择已激活评价员、批量分配与撤销分配；一人同一实验只有一个任务；提供可复制的实验链接 | M1/M2 |
| `REQ-09` | 实验有草稿、已发布、已关闭、已归档状态；可设置开放和截止时间；关闭或到期后禁止新保存和提交 | M1/M2 |

分享链接只帮助定位实验，不携带授权。未获分配的人不得通过猜测实验编号查看配置或数据。V1 不发送邀请邮件，不接受匿名公开投票；注册后等待管理员分配即可。是否已经注册不能决定其能看到哪些实验。

样品编码由管理员输入，按文本保留前导零；默认固定呈送顺序，默认仅向评价员显示编码。可显式开启显示样品名称。V1 不生成随机盲码、不随机分配呈送顺序；报告应记录这一设计限制，避免声称已消除顺序效应。

### 4.3 填写与提交

| 编号 | 要求 | 里程碑 |
| --- | --- | --- |
| `REQ-10` | 一个样品对应一份完整评价表；数字输入与滑杆联动，但初始为空，不自动填中间分数 | M1 |
| `REQ-11` | 显示指标解释、量程、步长及评分档位；分数改变时匹配档位；越界、步长不符、未填必答项均阻止提交 | M1 |
| `REQ-12` | 自动保存与手动保存草稿；显示保存中、已保存、保存失败；刷新可恢复；有未保存内容离开时提示 | M1/M2 |
| `REQ-13` | 逐样品提交、查看只读回执；重复点击或网络重试只产生一次提交；进度按最新已提交样品数计算 | M1/M2 |
| `REQ-14` | 管理员填写原因后退回指定样品；评价员修改后生成新修订；历史提交保留，不可覆盖 | M1/M2 |
| `REQ-15` | 真实模式支持跨设备恢复和并发冲突提示；提交成功必须取得服务端回执，不以动画结束冒充成功 | M2 |

允许标记“无法评价”的指标需在配置中明确开启，且必须填写原因；不允许把缺失自动变成 `0`。退回中的样品不纳入当前统计，直到重新提交。评价员不查看其他人评分或组均值，避免填写过程中受结果影响。

### 4.4 管理、统计和导出

| 编号 | 要求 | 里程碑 |
| --- | --- | --- |
| `REQ-16` | 管理员查看按实验、评价员、样品划分的完成状态；可筛选未开始、填写中、已完成和有退回项 | M1/M2 |
| `REQ-17` | 根据当前有效提交计算样本数、均值、样本标准差、中位数、最小值和最大值，展示均值图、箱线图和雷达图 | M1 |
| `REQ-18` | 按样品和题目汇总文字原文；保留原话并转义；默认以评价员代号展示 | M1 |
| `REQ-19` | 下载数值长表、文字长表、描述统计、任务覆盖率、配置和分析说明；支持 Excel，CSV 作为数值/文字长表的补充 | M1 |
| `REQ-20` | 推断分析遵循重复测量设计；显示方法、有效人数、排除规则、校正方法及不可计算原因 | M3 |
| `REQ-21` | 提供留一法组均值偏离诊断；不把偏离自动判作不合格，不自动剔除评价员 | M3 |
| `REQ-22` | 真实模式记录发布、分配、撤销、退回、关闭、停用、导出和分析等管理操作 | M2 |

## 5. 非功能要求

| 编号 | 要求 |
| --- | --- |
| `REQ-23` | 核心界面、空态、错误、图表标签和下载说明使用中文；技术错误转成可执行建议 |
| `REQ-24` | 适配 `360px` 手机与 `1440px` 桌面；填写主流程可用键盘完成；标签、焦点、错误提示可被辅助技术识别 |
| `REQ-25` | `demo` / `live` 数据、会话和能力显式隔离；真实服务异常不得回退到演示数据 |
| `REQ-26` | 项目路径 `/questionnaire/` 下直接打开、刷新、复制深链接、懒加载资源均可用；不要求服务器重写 |
| `REQ-27` | 发布物无服务端密钥、真实名单或真实答卷；数据库权限通过绕过前端的负面测试 |
| `REQ-28` | 文档、示例、迁移、部署说明与已实现行为同步；交付可重现的构建及回滚依据 |

V1 上限：每实验 `100` 名评价员、`12` 个样品、`30` 个数值指标、`10` 个文字题。该上限是本产品控制复杂度的决定，不是托管平台的限制。边界内必须完整处理，不得静默截断。

性能验收使用 `50` 人、`6` 样品、`12` 指标的合成数据：已加载页面内的普通操作应在 `200ms` 内给出反馈；长任务显示进度和取消；图表和 Excel 依赖按需加载。具体设备和耗时记录到验证报告，不把云服务响应时延承诺成固定事实。

## 6. 本版本不包含

- 支付、商业 SaaS、多租户、复杂组织权限。
- 通用问卷平台的跳题脚本、文件上传、任意 HTML、音视频题或自由代码插件。
- 随机盲码、拉丁方、样品顺序随机化、重复场次、感官小组训练系统。
- 自动把评价员排除出结果、自动生成科学结论或伪造显著性。
- 浏览器关闭后的后台发送、短信、邀请邮件、离线自动提交队列。

这些能力可以后续扩展，但不得先做上述扩展而遗漏 M1/M2 的完整闭环。
