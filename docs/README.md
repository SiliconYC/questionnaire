# 感官评价问卷系统 · 正式开发文档

版本：`1.0` · 编制日期：`2026-11-06` · 项目：`SiliconYC/questionnaire`

本套文档把简要设想整理为可直接实施的产品、数据、接口、部署与验收契约。系统以食品感官评价为首个应用场景：管理员配置实验、分配样品评价任务，评价员逐样品填写，管理员查看进度、分析和导出。

**当前实现状态：M1 完整演示已实现并通过本地验收；M2 接入代码已准备，真实服务未配置验收；M3 未启用。** 实际验证与限制见 [交付记录](delivery.md)，操作与构建入口见 [根 README](../README.md)。下文保留正式需求契约，不把外部服务准备代码当成真实功能已上线。

## 二、必须先理解的交付模式

| 模式 | 定位 | 必须真实工作的部分 | 明确的限制 |
| --- | --- | --- | --- |
| `demo` | GitHub Pages 上可直接使用的交互演示 | 建实验、导入、分配、填写、草稿、提交、退回、描述统计、文件下载 | 账户是演示身份，数据只在当前浏览器；没有真实邮件、跨设备同步或安全隔离 |
| `live` | 接入外部身份与数据库服务 | 真实身份、权限、多人共享、跨设备草稿、事务提交、审计 | 必须配置并验证外部服务；适合真实认证的站点承载方式见部署文档 |

`demo` 是可以操作和保存结果的应用。它只模拟需要外部系统的能力，不得把真实可实现的表单、计算和导出一起做成空壳。`live` 故障时展示错误，不得偷偷改用本地假账户或假数据。

## 三、文档约定

- **用户明确要求**：GitHub 仓库交付；GitHub Pages 展示；尽可能真实；允许分模块上线；文档阶段只编写设计，本轮用户已授权按此文档完成开发与发布。
- **本设计选定的默认值**：中文界面、单站点管理、数值与文字题、逐样品提交、固定样品顺序、`demo` / `live` 适配器。它们是本次设计决定，不冒称用户逐项确认。
- **必须**：本版本验收要求；**后续扩展**：不属于当前里程碑的验收范围。
- 需求编号为 `REQ-xx`，验收编号为 `AC-xx`，开发任务为 `Txx`。文档间使用这些编号对照。
- 字段、枚举及接口以 `04`、`05`、`06` 为准；数值算法以 `07` 为准；若产生实质冲突，先修正文档再实现，不由不同模块各选一种解释。
- 示例均为人工构造数据，不代表真实实验、真实用户或已经获得的科学结论。

## 四、给实现 Agent 的起点

先读 `01`、`03`、`09`、`10`、`11`。确认远端 `dev` 最新状态和已有实现，再从尚未完成的任务开始。建议目录已按实际实现落地，后续继续以当前源码及交付记录为准。

每个里程碑应交付：可访问地址、源代码提交、验证结果、实际运行模式、已完成能力和剩余外部配置。接入资源不足时仍应完成可部署的演示版本，并准确说明缺少的资源。
