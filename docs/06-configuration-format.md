# 06 · 配置与文件格式

## 1. 唯一配置模型

JSON 是规范化交换格式，Excel 是给管理员使用的编辑入口。两种输入必须转换为同一个 `ExperimentConfig`，经过同一份 [JSON Schema](contracts/experiment-config.schema.json) 和同一套跨字段语义校验。不能让 Excel 和界面各自定义评分规则。

格式版本固定为 `schema_version="1.0.0"`。遇到未知版本直接报告不支持；未来迁移需显式列出源、目标版本和变化，不猜测兼容。

完整示例见 [experiment-valid.json](examples/experiment-valid.json)。配置不包含用户、权限、答卷、会话、管理员账号或服务端密钥。站点隐私告知和数据保留策略来自可信站点配置，在发布时另行快照，不受导入文件覆盖。

## 2. JSON 顶层结构

| 字段 | 类型 | 必要约束 |
| --- | --- | --- |
| `schema_version` | 字符串 | 精确为 `1.0.0` |
| `experiment` | 对象 | 标题、说明、填写说明、时间、呈现选项 |
| `samples` | 数组 | `2–12` 个样品，数组顺序即固定建议顺序 |
| `indicators` | 数组 | `1–30` 个数值指标，数组顺序即显示顺序 |
| `text_questions` | 数组 | `0–10` 个文字题 |

顶层与各对象均拒绝未知字段，避免拼错字段后被默默忽略。字符串使用 Unicode NFC 规范化，标识/编码去除首尾空白；说明和题目正文不自动改写。导入预览显示规范化结果，用户确认后保存。

配置哈希使用 `SHA-256(UTF-8(JCS(normalized_config)))`，JCS 指 RFC 8785 的确定性序列化；先完成本项目规定的 Unicode/字段规范化，再进行 JCS，JCS 自身不负责 Unicode 规范化。答案/快照哈希另包含配置哈希、按稳定 ID 排序的完整输入行、修订 ID 与方法版本，不能仅哈希行数。依据见 [资料 DATA1](12-decisions-and-references.md)。

### 2.1 实验信息

| 字段 | 值/限制 |
| --- | --- |
| `title` | `1–100` 字符，纯空白不合法 |
| `description` | `0–2000` 字符，实验背景 |
| `instructions` | `0–4000` 字符，填写及品尝说明 |
| `time_zone` | V1 精确为 `Asia/Shanghai` |
| `opens_at` / `closes_at` | 带明确时区的 ISO 8601 字符串或 `null`；两者存在时前者早于后者 |
| `display_sample_names` | 布尔；默认模板为 `false` |
| `design` | V1 精确为 `within_subject_complete` |
| `sample_order` | V1 精确为 `fixed` |

两端时间均空时仍受站点最长保留与处置策略约束，见 [08](08-security-and-privacy.md)。导入已有过去日期的配置允许形成草稿；发布时必须检查尚有可用时间，过期实验不得发布。

### 2.2 样品

| 字段 | 类型/含义 |
| --- | --- |
| `sample_id` | 稳定短标识，例如 `s_a`；配置内唯一 |
| `code` | `1–32` 字符的样品编码；如 `001` 必须保留为字符串，配置内唯一 |
| `admin_name` | `1–100` 字符的管理员名称 |
| `display_name` | `0–100` 字符的评价员可见名称；关闭名称显示时不返回该字段 |

`display_sample_names=true` 时，全部样品的 `display_name` 必须非空。编码和 ID 均区分大小写；规范化后重复即错误，不自动追加后缀。评价员端始终显示编码，不能以数组下标代替稳定 ID。

### 2.3 数值指标

| 字段 | 类型/含义 |
| --- | --- |
| `indicator_id` | 配置内唯一短标识 |
| `category` / `label` | 大类 `1–50` 字符、指标名称 `1–100` 字符 |
| `description` | `0–2000` 字符说明 |
| `kind` | `continuous` 连续形式或 `anchored` 档位说明形式 |
| `min` / `max` | 允许范围，`-10000` 至 `10000`，最多两位小数，且 `min < max` |
| `step` | `(0,10000]`，最多两位小数；从 `min` 起的输入步长 |
| `required` | 是否必须评分或填写被允许的无法评价原因 |
| `allow_not_evaluable` | 是否显示“无法评价”；选择后原因必填 |
| `direction` | `higher_better`、`lower_better` 或 `neutral`；仅含义说明，不自动生成总分 |
| `analysis_scale` | `interval` 或 `ordinal`；前者是按等距评分分析的设计声明，不能由控件类型推断 |
| `anchors` | 档位数组；连续形式必须为空数组，档位形式 `2–10` 项 |

短标识统一匹配 `^[a-z][a-z0-9_-]{0,63}$`。`kind` 描述界面，`analysis_scale` 描述统计假设；二者不是同一概念。量程 `1–10` 必须明确记录为 `min=1,max=10`，原稿的 `110` 不得直接解释为数值 `110`。

量程整数化后必须满足 `(max-min) % step == 0`，分数必须是 `min + n × step` 且不超过 `max`。例如 `min=1,max=10,step=0.5` 接受 `7.5`，拒绝 `7.3`。前端和后端均按精确十进制/整数刻度验证。

先用十进制文本解析或精确十进制库检查小数精度，再转换为百分刻度整数；尾随零不增加有效小数位。不得直接用 `Number.isInteger(value * 100)`、浮点取模或四舍五入判断合法性。Schema 有意不设置 `multipleOf:0.01`，避免部分验证器的默认浮点除法误拒合法值；精度错误由语义层返回 `DECIMAL_PRECISION`。依据见 [Ajv 的精度说明](https://ajv.js.org/options.html#multipleofprecision)。

[小数网格合法示例](examples/decimal-grid-valid.json) 使用 `min=0.29,max=0.57,step=0.07`，必须接受 `0.29,0.36,0.43,0.50,0.57`，拒绝 `0.30` 和三位小数 `0.291`。此例与普通配置均须通过结构和语义两层检查。

### 2.4 档位边界

每个档位为 `{label, from, to}`，标签 `1–200` 字符。区间按顺序连续覆盖整个量程，第一项 `from=min`，最后一项 `to=max`，相邻项前 `to` 等于后 `from`，且每项 `from < to`。

**边界统一采用左闭右开，最后一档右闭。** 例如 `[1,4)`、`[4,7)`、`[7,10]`：`4` 属第二档，`7` 属第三档，`10` 仍合法。不得把边界显示为容易误解的“1–4、4–7”。页面可显示“1 ≤ 分数 < 4”等明确文字。

边界必须在指标的步长网格上。档位用于解释分数，不限制评价员只能选某档，也不把数值自动改成该档中点。连续形式只有描述，无档位高亮。

### 2.5 文字题

字段为 `text_question_id`、`label`、`description`、`required`、`max_length`。名称 `1–100` 字符，说明最多 `2000` 字符；上限是 `1–2000` 的整数，模板默认 `500`。问卷题目按数组顺序对每个样品重复显示。

### 2.6 编辑草稿

向导内部使用 `DraftExperimentConfig`：字段集合、对象结构、枚举与正式配置相同，所有键仍存在，但标题、名称、编码和说明可为空字符串，样品/指标/档位/文字题数组可为空，指标 `min/max/step` 可为 `null`。编辑时尚未满足范围关系、档位连续覆盖、必填名称或最小条目数，可以保存并返回 `publish_issues`，让用户下次接着完善。

草稿仍执行类型检查、未知字段拒绝、长度/数量上限、有限数值与两位小数限制、稳定 ID 的格式和唯一性。已存在对象的 ID 不允许为空；创建对象时由编辑器分配稳定 ID。答案提交仍使用 [04](04-data-model.md) 的另一种“答卷草稿”，不要混淆两类草稿。

本目录 JSON Schema 只定义正式交换/发布配置，不用于把不完整编辑草稿误判成不可保存。发布、文件导入和正式配置导出必须完整通过该 Schema 与语义校验；未完成草稿禁止发布/导出正式模板，但可以继续保存到工作区。接口参数需明确使用两种不同类型。

## 3. Excel 模板

使用 `.xlsx`，不接受 `.xls`、`.xlsm`、宏、外部链接或公式。Excel 格式具体解析能力依赖所选库，必须验证文件类型和实际内容，不能只看扩展名。

模板包含以下五张工作表，可另附一张不参与导入的 `模板说明`：

| 工作表 | 列名 | 映射 |
| --- | --- | --- |
| `实验信息` | `字段`、`值` | 一行一个实验字段；含格式版本 |
| `样品` | `样品ID`、`样品编码`、`管理名称`、`显示名称` | 转为 `samples` |
| `指标定义` | `指标ID`、`大类`、`指标名`、`说明`、`形式`、`量程下限`、`量程上限`、`步长`、`必答`、`允许无法评价`、`方向`、`分析尺度` | 转为 `indicators` |
| `评分档位` | `指标ID`、`序号`、`描述`、`下限`、`上限` | 按指标关联，再按序号形成 `anchors` |
| `文字题` | `题目ID`、`题目`、`说明`、`必答`、`字数上限` | 转为 `text_questions` |

`实验信息` 的字段映射如下，必须各出现一次：

| Excel 字段 | JSON 字段 | 值 |
| --- | --- | --- |
| `格式版本` | `schema_version` | `1.0.0` |
| `实验名称` | `experiment.title` | 文本 |
| `实验说明` | `experiment.description` | 可空文本 |
| `填写说明` | `experiment.instructions` | 可空文本 |
| `时区` | `experiment.time_zone` | `Asia/Shanghai` |
| `开放时间` | `experiment.opens_at` | ISO 8601 文本，空白转 `null` |
| `截止时间` | `experiment.closes_at` | ISO 8601 文本，空白转 `null` |
| `显示样品名称` | `experiment.display_sample_names` | 布尔 |
| `实验设计` | `experiment.design` | `within_subject_complete` |
| `样品顺序` | `experiment.sample_order` | `fixed` |

表头按名称映射，允许调整列顺序；缺列、重复列、未知列报错。未知工作表报错，唯一例外是 `模板说明`。`评分档位`、`文字题` 可只有表头，其他必需表不允许为空。完全空白行忽略，不合并单元格、不用颜色表达字段含义。

布尔仅接受真正布尔值或精确文本 `true/false/是/否`。形式仅接受 `continuous/anchored`，方向和分析尺度使用 JSON 枚举原值；模板说明给中文对照，不依赖任意中文别名猜测。数值仅接受有限数字或标准十进制文本，不接受千分符、百分号、区域化逗号、小数以上两位或 Excel 错误单元格。

样品编码必须是文本单元格。数字 `1` 配显示格式 `000` 不等于原始编码 `001`，这种输入应要求管理员改为文本，不能静默猜测。日期必须是带时区的文本，拒绝 Excel 日期序列值，避免时区和日期系统歧义。

档位 `序号` 从 `1` 连续递增、无重复；引用的指标必须存在且为 `anchored`。文本等所有单元格均拒绝公式，即使库提供缓存结果也不使用。

## 4. 导入流程与错误

文件最大压缩体积 `5MiB`；解析后累计不超过 `20000` 个非空单元格、`20MiB` 文本/解压预算，单个文本长度仍受字段上限限制。解析在可终止的工作线程中执行，`10s` 超时中止。读取库若不提供解压限额，先用受限 ZIP 检查器检查条目数量/声明体积，并保留实际解压计数限制；不能只相信 ZIP 元数据。以上为本项目输入边界。

先检查文件容器，再规范化、Schema 校验、语义校验，最后生成预览。导入确认前不写业务数据库；任何错误不得部分导入。返回错误对象：

```json
{
  "code": "ANCHOR_OVERLAP",
  "path": "/indicators/0/anchors/1/from",
  "sheet": "评分档位",
  "cell": "D3",
  "message": "本档下限与上一档上限不一致，请检查重叠或缺口。"
}
```

JSON 文件没有 `sheet/cell` 时省略两字段。至少区分重复 ID、重复编码、引用不存在、量程颠倒、小数精度超限、非法步长、档位缺口、档位重叠、不支持版本、未知字段和过大文件。示例非法案例见 [invalid-cases.json](examples/invalid-cases.json)。

JSON Schema 负责结构、类型与简单范围；唯一 ID、跨字段日期、档位拼接、十进制精度、步长网格、编码规范化重复和语义必填由第二层校验负责。Schema 校验成功不能宣称配置完整合法。

## 5. 导出契约

### 5.1 Excel 结果文件

所有输出均使用同一冻结分析快照，文件名形如 `questionnaire_<experiment_id>_<snapshot_id>_<UTC时间>.xlsx`。标题只出现在内容中，不直接拼入任意文件路径。

| 工作表 | 内容/必须列 |
| --- | --- |
| `导出说明` | 模式、是否示例、实验/配置/快照 ID、数据版本、生成时间、时区、纳入排除规则、软件版本 |
| `数值明细` | `participant_code, sample_id, sample_code, indicator_id, category, label, value, missing_reason, response_id, revision_id, revision_no, submitted_at, config_version_id` |
| `文字明细` | `participant_code, sample_id, sample_code, text_question_id, value, response_id, revision_id, submitted_at` |
| `描述统计` | `sample_id, indicator_id, n_valid, n_missing, mean, sd, median, q1, q3, min, max` |
| `任务覆盖` | 评价员代号、任务状态、各样品状态、纳入/排除原因；不导出草稿答案 |
| `实验配置` | 规范化 JSON 文本及配置哈希，可分多行；包含管理员可见名称 |
| `推断分析` | M3 开启且任务完成时写正式结果；否则写“未提供/不可计算”及原因，绝不放假数值 |

`n_missing` 在描述统计中指已经纳入的当前提交中该指标为空的数量；未提交、撤销、停用等不混入这个数字，在 `任务覆盖` 单列。已有合法 `0` 不能导出为空。不可计算量输出空单元格并有状态/说明列；不能导出为 `0` 或字符串 `NaN`。

### 5.2 CSV 与配置

CSV 分别导出数值或文字长表，采用 UTF-8 BOM、逗号分隔、CRLF 换行；包含逗号、换行或双引号的字段按 CSV 转义。CSV 不冒充多工作表 Excel。

所有用户输入的文本在 Excel 明确作为字符串单元格写入。CSV 中可能被电子表格执行的前缀（`=`, `+`, `-`, `@` 及全角变体，以及制表/回车/换行等前导控制字符）按文本安全策略处理；对危险字符串加前导单引号并用标准双引号包裹、内部引号翻倍，在导出说明记录此显示层转义。数值评分保持数值类型；不得把负分数错误转换为危险公式，也不得修改数据库原文。

CSV 转义不能保证所有电子表格软件在保存后重新打开仍保持安全；以明确字符串类型的 `.xlsx` 作为人工查看的首选。实施时至少验证目标 Excel 版本首次打开的行为，并在 CSV 下载说明提示不要执行公式。不能把加引号宣称为跨软件绝对防护，依据见 [资料 WEB2](12-decisions-and-references.md)。

配置导出生成符合本 Schema 的 `.json` 或本模板 `.xlsx`；再次导入必须保持题目、ID、量程、顺序和档位语义一致。导出文件不包含令牌、数据库连接信息、邮件凭据或真实用户邮箱。

## 6. 兼容性决定

原稿的三表模板没有稳定 ID、明确步长与无歧义档位边界，且将样品混在实验信息中。本版本采用五表正式格式。旧三表文件不得被静默当成新模板；V1 提示“请按正式模板整理”，不建设无法可靠推断的自动迁移器。
